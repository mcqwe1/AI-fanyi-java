## 一、项目概览

**一句话定位**：AI 视频/音频翻译平台。上传视频或音频 → 抽音频 → ASR 转写 → LLM 翻译 → 生成字幕/译文/烧录/配音。

**功能全景**：
- **普通翻译**：视频/音频 → SRT 字幕 + 译文 TXT，可烧录字幕进视频（样式可调带预览）
- **术语库（KB）翻译**：一系列视频共用一张术语表，Gemini 联网抽专名，译法统一
- **文本翻译**：粘贴文本 / 上传 txt/md/srt/vtt，双语对照，srt/vtt 保留时间轴
- **字幕轴编辑器**：全屏页，播放器 + 字幕叠加 + 行编辑/打点/插删行
- **TTS 配音**（2026-07-18 新增）：译文逐行合成语音 → 按时间轴拼配音轨 → 合成回视频
- **术语库管理页**（2026-07-18 新增）：跨项目术语增删改查 + 批量移动/复制/删除

**本目录是便携版主线**（自 2026-07-11 起新代码先改这里，验证后等指令再同步 `D:\aifanyi` 本地版）。与本地版差异：
- 数据库 **H2 嵌入式文件库**（`backend/src/main/resources/schema.sql`，MODE=MySQL，幂等建表 + ALTER 升级 + 种子 demo 用户），无需 docker；可用 `AIFANYI_DB_URL/USER/PASSWORD/DRIVER` 切外部库
- **无 Redis**（死依赖已删）、**无 docker 一切依赖**
- 前端构建产物拷进 `backend/src/main/resources/static`，Spring Boot 同端口托管（hash 路由）
- 路径全部环境变量化：`AIFANYI_PORT` / `AIFANYI_STORAGE_ROOT` / `FFMPEG_PATH` / `AIFANYI_JWT_SECRET`

## 三、最终用户使用说明（便携包）

*（来源：portable/README-使用说明.md，随包分发）*

零依赖：不需要安装 Java / Docker / MySQL / Node / Python，解压即用。

1. 双击 `start.bat`（首次约 20 秒），浏览器自动打开 `http://localhost:8080`
2. demo / demo123 登录（可注册自己的账号）
3. 首次登录弹**配置向导**：填 Groq Key（语音识别，免费注册 console.groq.com）+ LLM 配置（翻译，任何 OpenAI 兼容接口，推荐 DeepSeek）。右上角「教程」有图文
4. 首页选模式 → 上传 → 等完成 → 下载 SRT / TXT / 烧录 / 配音
5. 用完 `stop.bat` 关闭

| 目录/文件 | 作用 |
|---|---|
| `start.bat` / `stop.bat` | 一键启停（可带端口参数 `start.bat 9090`） |
| `data\` | 全部用户数据：数据库/任务文件/密钥（备份搬家拷它即可） |
| `data\backend-8080.log` | 后端日志，出问题先看 |
| `app\` `runtime\` `bin\` | 程序、内置 JRE、内置 FFmpeg，勿动 |
| `ai-service\python` `ai-service\models` | 内置 Python 运行时 + 4 个离线 Whisper 模型（完整版） |
| `setup-ai-service.bat` | 仅精简版需要（完整版开箱即用） |

**完整版能力**：本地 Whisper base/small/medium/large-v3 全内置离线加载，零下载零配置；有 N 卡自动 GPU 加速，无 N 卡自动 CPU；Edge-TTS 配音免费零配置。

常见问题：端口被占 → `start.bat 9090`；数据搬家 → 拷整个文件夹或 `data\`；安全 → 服务只听 localhost，密钥在本机 `data\` 数据库里，别把 `data\` 发给别人。

## 四、数据流与流水线（后端核心）

### 普通模式流水线（`TaskPipeline.runAsync`）
```
上传 → 存 source.mp4 → PENDING
 → FFmpeg 抽 audio.mp3            EXTRACTING_AUDIO(10%)
 → AsrProvider 转写（词级时间戳）   TRANSCRIBING(30→55%，实时进度)（VAD 并行计算）
 → 反幻觉 + 时间轴对齐（见下）
 → [KB 模式] Gemini 抽术语入库      BUILDING_KB(50%)
 → OpenAiTranslator 批量并发翻译   TRANSLATING(60%)
 → 落库 subtitle 表 + 生成 subtitle.srt
 → DONE / 任一步异常 FAILED
之后可选：烧录（BURNING→DONE）/ 配音（独立 dub_status，不进主状态机）
```

### 反幻觉 + 时间轴后处理链（2026-07-10 重做）
```
HallucinationFilter.filter        黑名单套话(含"晚安/おやすみ"家族) + 复读折叠 + 数字连跑
→ dropNonSpeech(VAD)              与语音区间重叠<250ms → 幻觉丢弃(文本无关)
→ alignToSpeech(VAD)              双向对齐：早出后移/晚出前拉/终点修剪/外扩
→ [VAD 不可用退回 ffmpeg silencedetect -50dB，不做对齐]
→ shiftAll(probeAvStartOffsetMs)  补回 A/V 流 start_time 偏移(|off|≥50ms 才动)
→ fix                             去空白/去重叠/最短时长兜底
```
VAD 区间来自 ai-service `/vad`（Silero threshold=0.3 + pad 120ms），与 ASR 并行。
单测：`SubtitleTimingFixerTest`(15例) / `HallucinationFilterTest`(3例)。

### 状态机
主状态 `TaskStatus`：PENDING / EXTRACTING_AUDIO / TRANSCRIBING / BUILDING_KB / TRANSLATING / BURNING / DONE / FAILED。
**配音不进主状态机**：走 `translation_task.dub_status`（null/DUBBING/DONE/FAILED）+ `dub_progress` + `dub_error` + `dub_notice` 四列——配音是 DONE 任务的附加操作，成败绝不影响翻译成果与主状态（2026-07-18 解耦，之前配音失败会把整个任务打成 FAILED 是设计错误）。`dub_notice` 是**成功时**的提示（个别行译文过长），前端黄色 alert，与红色 `dub_error` 区分。

## 七、TTS 配音（2026-07-18 新增，2026-07-29 时间轴与性能重做）

**流程**：DONE 的视频任务 → 「配音」进 `/dub/:id` 全屏页 → 选引擎音色/语速/是否保留原声 → 试听 → 开始配音（异步）→ **并发**逐行译文 TTS → 解码为 44.1kHz PCM WAV 并裁掉首尾静音 → 超槽行 atempo 变速压缩 → **按 startMs 采样级写入整轨** → 混入原视频（视频流直拷；保留原声=原声压 15% amix）→ `dubbed.mp4`。

### 时间轴设计（2026-07-29 重做，根治「字幕音频不同步」）

**旧方案的缺陷（已废弃）**：`cursor` 传送带式拼接——插静音→追加片段→`cursor += 片段时长`。某行 TTS 音频长于其字幕槽位时，下一行被顺推，**误差单调累积**。实测 25 秒密集口播（9 行、间隔 200ms）末行漂移 **10.1 秒**；再叠加 mp3 帧量化（26ms/帧）与 LAME 编码器延迟的逐段漂移。这就是闲鱼客诉「字幕音频不同步」的根因。

**新方案**：`WavTrackAssembler` 纯 Java 采样级拼轨。
```
每行 TTS → decodeToWavMono44k（含 -50dB 首尾静音裁剪）
        → fitTempo 判定是否超槽 → 超则 atempoWav 压缩（保音高，上限 1.4x）
        → WavTrackAssembler.assemble：按 startMs 换算绝对采样位置直接写入
           空隙天然为 0（静音），重叠区逐样本饱和混音（钳制到 int16）
```
- **每段位置只由自己的 startMs 决定**，某行超长只与下一行重叠，**绝不推移后续任何行**——误差不累积（单测 `overlongClipDoesNotShiftNextClip` 锁定该行为）
- 全程 PCM，无 mp3 帧量化/编码器延迟漂移
- **裁掉 TTS 首尾静音**（edge-tts 实测首 ~180ms / 尾 ~590ms）：首部留白正是配音晚出的固定偏差；尾部留白白占槽位、逼出不必要的变速。实测密集场景重叠行 4→0、最大重叠 558ms→85ms、平均变速 1.35x→1.26x
- 压到 1.4x 仍装不下的行（译文本身过长）：写 `dub_notice` 提示用户具体行号，前端黄色 alert 展示，可去字幕编辑器改短或降低语速重配

**实测**（E2E，`dense_test.mp4` 8 行密集对白）：每行配音起点 = 字幕起点，**偏差恒为 0**；VAD 复测配音轨语音起点与字幕最大偏差 72ms（且不随行数增长）。

### 性能设计

逐行合成走独立线程池并发（`TTS_CONCURRENCY`，默认 6），每行只起 1~2 个 ffmpeg 进程（解码 + 可选变速）；静音生成与轨道拼接**零进程**（旧方案 300 行需约 700 次进程创建 + 300 次串行网络请求）。进度多线程安全单调递增（`dubProgress` 同步块）。单行合成失败重试 3 次（指数退避），最终失败的错误信息带行号。

**引擎注册表 `TtsEngines`（单一事实源）**——设置页三张卡片，音色格式差异全部在映射表吸收，用户只看中文友好名：

| 引擎 id | 名称 | 配置要求 | 音色 |
|---------|------|---------|------|
| edge | Edge-TTS（微软语音） | **零配置**（需联网），经 ai-service /tts | 晓晓/晓伊/云希/云健/云扬/云夏/晓北(东北)/晓臻(台)/曉曼(粤)/七海(日)/Aria/Guy |
| siliconflow | 硅基流动 CosyVoice | 仅填 API Key（base/model 预设） | Alex/Benjamin/Charles/David/Anna/Bella/Claire/Diana（value 为「模型:音色」全称） |
| openai | 自定义 OpenAI 兼容 | Base/Key/模型自填 | Alloy/Echo/Fable/Onyx/Nova/Shimmer |

**关键设计**：
- provider 音色**原样发送不做猜测改写**（改错比不改糟）；edge→EdgeTtsProvider，其余→OpenAiCompatTtsProvider
- 配音状态独立（dub_status 三列 + dub_notice），失败只标配音失败，翻译成果不受影响，改配置直接重配
- dub 端点**前置同步校验**（未选引擎/缺 key 当场报错，任务纹丝不动）
- 重启恢复：中断配音只重置 dub_status=FAILED
- MVP 边界：音色任务级全局（非逐行）；音频任务暂不支持配音产出

## 八、术语库（KB）设计

*（来源：docs/术语表流程.md）*

**作用域**：术语表挂「系列项目」（kb_project），一系列视频共用、越攒越准。

```
① KB 模式上传 → 选系列项目
② ASR 转写全文
③ BUILDING_KB：GeminiClient.extractTerms（gemini-3-flash-preview-search 联网核实译法）
   按六大类抽取：人名/地名与地址/机构组织与品牌/作品名/文化专有项/科技专名
   每条 {原文, 译法, 类别, 依据}
④ 入库 upsertAutoTerms：同项目 source_term 已存在→跳过（不覆盖人工/已审）；新词→origin=auto
⑤ 人工审核（随时）：KbMode 内联表 或 /glossary 管理页 改译法/类别/启停/增删/跨项目移动复制
⑥ TRANSLATING：loadGlossary 取 enabled=1 → 原文→译法映射（长词优先防子串误命中）
   每批只注入「该批文本中出现的」术语进 prompt（省 token 可规模化）
   翻译模型 = 抽术语的 Gemini 剥 -search 加 -nothinking（关思考提速 ~15s/批→~3s）
⑦ 落库字幕 + SRT
```

自定义术语抽取提示词：设置页「风格与术语」可覆盖内置（支持 {sourceLang}/{targetLang}/{transcript} 占位符）。

## 十、ai-service 微服务

FastAPI，端口 **8001**。正常**无需手动启动**：后端 AiServiceLauncher 按需 spawn（venv/内置 python 的 uvicorn），健康检查复用已存活进程。

| 接口 | 用途 |
|------|------|
| GET /health | 探活（Launcher 用） |
| POST /transcribe | 本地 faster-whisper 转写（**批量推理**；词级时间戳；GPU cuda+int8_float16，CUDA 缺失自动降 CPU，转写中途 CUDA 错误再降级重试；`progress_path` 写转写进度） |
| POST /vad | Silero VAD 语音区间（供时间轴对齐） |
| POST /tts | Edge-TTS 合成（text/voice/rate → mp3 字节；2026-07-18 新增） |

**批量推理（2026-07-29 新增，转写提速核心）**：优先走 `BatchedInferencePipeline`（按 VAD 切块并行解码），失败/OOM 自动回退经典串行路径，真 CUDA 运行库错误则上抛交由外层降级 CPU。
- `WHISPER_BATCH_SIZE`（默认 8，设 0 关闭批量）、`WHISPER_CPU_THREADS`（默认 = CPU 核数 − 1，上限 8；旧默认只有 4 跑不满多核机）
- **`without_timestamps=False` 必须显式传**：该参数默认 True，会把整个 VAD 块（最长 30s）合成一条 segment，字幕变成 30 秒一大条。这是接入批量管线最容易踩的坑
- 实测（250s 音频 / base 模型）：CPU 串行 55s → CPU 批量 **12s（4.6x）**；GPU 串行 25s → GPU 批量 **15s（1.67x）**。19 分钟音频 CPU 批量仅 49s

**转写进度回报（2026-07-29 新增）**：请求带 `progress_path`，服务边消费 segment 生成器边把 0~1 写入该文件；后端 `LocalWhisperProvider` 每 2 秒轮询该文件（同机文件传递，零协议改动），映射到主进度 30~55%。Groq 分块路径按块回报。解决「转写期间进度条长时间停在 30% 像卡死」的体感问题。实测串行路径 7 次平滑更新，批量路径 4 次（25%→51%→76%→99%）。

**模型加载三层防御**：① `models/faster-whisper-<size>/` 本地库优先（含 model.bin 即离线）；② 自动下载兜底（HF_ENDPOINT=hf-mirror + NO_PROXY 绕代理 + 超时放宽 + 3 次退避）；③ 报错带操作指引。
**Python 版本**：本机 3.14 过新无 wheel，运行时必须 3.12（内置 `python/` 或 `.venv`）。

## 十一、打包与分发

```
powershell -ExecutionPolicy Bypass -File build-portable.ps1   # 构建 dist/aifanyi-win64
powershell -ExecutionPolicy Bypass -File pack-release.ps1     # dist 压 zip（自动排除 data）
```

6 步：npm build 前端 → 静态资源并入后端 → mvnw package fat jar → 组装 dist（**自动拷 ai-service/python 运行时+models 模型库**，并确保 edge-tts 已装）→ jlink 精简 JRE → 完成。

**完整版构成（~8.1GB）**：fat jar + jlink JRE + ffmpeg + 便携 Python 3.12.8（含 faster-whisper/edge-tts/fastembed/GPU 库 cublas·cudnn，2.3GB）+ 4 个 Whisper 模型（base 142M/small 464M/medium 1.5G/large-v3 2.9G，源=modelscope gpustack）+ 句向量模型（fastembed ONNX，240MB，全能AI翻译的术语近义发现用）+ 启动脚本。目标机零依赖。
根目录 `start.bat`/`stop.bat` 是指向 dist 的转发器。`portable/` 是打包模板源。

**教训（务必记住）**：打包脚本会 `Remove-Item dist` 整个重建——python/models 曾只手工放在 dist 里被洗掉两次，现已让开发目录 `ai-service/python`+`ai-service/models` 作为源、脚本自动拷贝，永久闭环。**打包前先停 dist 里的进程**（java + ai-service 的 python），否则文件占用打包失败——`stop.bat` 现已一并杀掉本安装目录下的 python（按 `ExecutablePath` 前缀匹配，不会误杀用户自己装的 Python），2026-07 实测 1→0 有效。

**句向量模型的坑（2026-07 亲历）**：fastembed 默认把模型下到**系统临时目录** `%TEMP%\fastembed_cache`，清理临时文件就没了（本项目已被清掉过一次）。故必须显式指定 `cache_dir` 到 `ai-service/models/fastembed`，`build-portable.ps1` 会校验它是否存在并给出补齐命令。模型已随包内置时 `_load_embedder` 会置 `HF_HUB_OFFLINE=1` 直接离线加载——否则 fastembed 仍会先请求 Hub 校验版本，断网用户要卡满整个重试退避才回落本地。

## 十二、已知坑（历史经验，务必记住）

1. **写 .ps1 要带 BOM**（中文 Win + PS5.1，否则中文乱码解析失败）
2. **PS 5.1 读 UTF-8 无 BOM 的 .env 按 GBK**：中文注释行尾会吞换行坑掉下一行 env。已根治（`Get-Content -Encoding UTF8`）
3. **ai-service 跑 8001**（8000 被本机 node 占）
4. **faster-whisper GPU**：CTranslate2 只认 PATH；main.py 启动把 `nvidia/*/bin` 前置进 PATH 才能加载 cublas/cudnn。GPU=GTX1660S 6G，cuda+int8_float16
5. **本机 Python 3.14 太新**：ai-service 用独立 3.12 运行时
6. **Git Bash 内联中文按 GBK 发出**→后端 Invalid UTF-8；测 API 用 ASCII 或写文件。curl 上传用 `D:/...` 不用 `/d/...`
7. **后端日志 `run-backend.ps1 *> log` 是 UTF-16**，读要 `iconv -f UTF-16LE`
8. 重启后端先杀 8080
9. **翻译性能**：批 40 并发 8（`LLM_BATCH_SIZE`/`LLM_CONCURRENCY`）；按 index 对齐回填（漏译只影响单行）；**翻译端点用 deepseek 直连**（api.deepseek.com ~1.7s/批；`api.pioneer.ai` 中转极慢且断流）。配音并发 `TTS_CONCURRENCY`（默认 6）；转写批量 `WHISPER_BATCH_SIZE`（默认 8，0=关）/ `WHISPER_CPU_THREADS`（默认核数−1）
10. **Whisper 模型下载国内是重灾区**：hf-mirror 对重试 IP 限流（TLS RST → SSL EOF）；Clash TUN 连"直连"都接管；新 huggingface_hub 走 httpx 不读注册表代理。三层防御见第十节。**现完整版已内置全部模型，此坑仅精简版遇到**
11. **ai-service 冷启动并发导入死锁**：/vad 与 /transcribe 首请求并发惰性导入 → `_ModuleLock DeadlockError`。修复=启动预热导入
12. **CUDA 库缺失自动降级**：`_cuda_runtime_ok()` 判定后走 CPU 并提示补装；转写中途 CUDA 错误降级重试一次
13. **Gemini 官方端点必须带 `/openai` 后缀**（`.../v1beta/openai`）：填 `.../v1beta` 会打到原生接口，Bearer 认证被当 OAuth 拒绝报 401 "Expected OAuth 2 access token"
14. **large-v3 的 CT2 模型用 `vocabulary.json`**（非 vocabulary.txt），缺它报 "Cannot load the vocabulary"
15. **勿在项目文件里存密钥/密钥笔记**——models/README.txt 曾夹带 API key 差点随包分发
16. **打包被占用挡住**：dist 的 ai-service python 是后端子进程转孤儿，stop.bat 不杀它；打包前需手动清（或喊 Claude 清）
17. **`BatchedInferencePipeline` 的 `without_timestamps` 默认 True**：不显式传 False 会把整个 VAD 块（≤30s）合成一条 segment，字幕变成 30 秒一大条。接批量管线必踩
18. **跑 `mvn test` 前先停开发后端**：H2 是文件库，运行中的后端持有 `data/db/aifanyi.mv.db` 排它锁，测试建上下文时报 `MVStoreException: The file is locked`（看似 schema 出错，实为锁）。`spring-boot:run` 退出后 JVM 可能残留，用 `Get-CimInstance Win32_Process -Filter "Name='java.exe'"` 查 PID 再杀
19. **配音时间轴绝不能用 concat 传送带**：累积漂移，密集口播 25 秒就能漂 10 秒。必须按 startMs 绝对定位（见第七节）
20. **TTS 返回的音频自带首尾静音**（edge-tts 实测首 ~180ms/尾 ~590ms）：不裁掉则首部留白 = 配音固定晚出，尾部留白白占槽位
