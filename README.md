# 译审团 · 多智能体质量增强系统

> 面向「**单个大模型在生产环境不可靠**」问题的多智能体系统，落地场景为视频翻译。
> 核心哲学：**模型负责语言能力，系统负责事实性与可靠性。**

---

## 一、解决什么问题

把一个视频丢给任何单一大模型翻译，会稳定出现四类失效：

| 失效 | 具体表现 |
|---|---|
| **知识过时** | 新游戏角色「アベンチュリン」被自信地音译成"阿文丘林"，官方中文其实叫**砂金** |
| **过度自信** | 模型自报 high confidence，却拿不出任何依据；编造一个维基链接当证据 |
| **前后不一致** | 同一个专名，第 1 批译法与第 10 批不同，全片摇摆 |
| **输出不可靠** | 一批 40 行只返回 23 行，静默丢失，成品里塌出一大块未翻译文本 |

这些问题**靠 prompt 调优治不了**，需要系统层面的治理。

## 二、系统怎么治

```
① 路由        文件类型判定（纯代码，零 token）
② 读源        视频/音频/文本 → 统一中间态（唯一允许终止任务的关口）
③ 场景推测    主 Agent 在档案池中匹配领域，激活对应专家        [1 次 LLM]
④ 专家扇出    N 个领域专家并行，各自固定 DAG：
                A 抽候选词 + 判定是否需联网          [1 次 LLM]
                B 搜索 ≤2 次（代码执行、代码计数、搜完封口）
                C 依据检索结果定译法 + 选策略        [1 次 LLM]
⑤ 仲裁        去重 → 投票 → 五级确定性裁决链 → 四特征置信度算分（纯代码）
⑦ 状态机      按证据档位分档落库：采信 / 待审 / 仅本次 / 丢弃
⑧ RAG 翻译    术语精确匹配注入 + 滚动窗口上下文（组内串行、组间并发）
⑨ 出口        字幕落库 + SRT
⑩ 观测        本地 trace 实时时间线 + LangSmith 全文上报
```

### 六类失效 → 六项设计

**1. 知识过时 → 工具使用与验证闭环**
模型只表达意图（返回 `{"status":"NEED_SEARCH","queries":[...]}`），**搜索由代码执行、代码计次、搜完物理封口**。用结构化 JSON 协议而非 function calling，以兼容用户自填的任意 OpenAI 端点（实测：部分中转站连 `thinking:{type:disabled}` 都不认）。

**2. 过度自信 → 证据分层置信度**
四特征加权（自报 0.25 / 跨专家一致 0.35 / 权威命中 0.25 / 词形结构 0.15），再套**证据档位天花板**：

| 证据强度 | 分数上限 | 结果 |
|---|---|---|
| 代码核验过的权威来源 | 0.95 | 可自动采信 |
| 多专家独立一致 | 0.82 | 至多待人工确认 |
| 单模型裸猜 | 0.59 | 绝不入库 |

模型自报的权威链接**必须与真实检索结果比对核验**，域名须在白名单内，否则连策略字段一起降级——*自报不当证据，一切证据过代码*。

**3. 单视角偏差 → 多专家提案 + 确定性仲裁**
不同领域画像注入的子 Agent 并行独立提案，投票 + 五级裁决链合并（同输入永远同输出，可复现）；势均力敌的分歧**显式标记交人工**，而不是被单模型内部悄悄抹平。

**4. 输出不可靠 → 编排层兜底**
固定 DAG（`advance()` 遇回退直接抛异常）+ 硬预算（单实例 3 工具 / 2 搜索 / 30s，全局 90s）。子 Agent 超时不是白跑：结果累加器挂在任务对象上，编排器**提交前**即持有引用，线程被 cancel 后仍能取回部分成果。

**5. 无记忆 → 数据飞轮**
产出按置信度分档入库，同一领域下次任务自动复用；**跨任务同结论自动加分转正**（按任务 ID 防重试刷分）；人工修正的条目永久锁定，AI 永不覆盖。系统随使用变准，而非每次从零开始。

**6. 不可观测 → 双轨追踪**
本地 trace 表驱动实时执行时间线（用户看人话）；LangSmith 上报完整提示词、搜索结果、术语表（开发者看细节）。每道处理环节记账，"数据是谁删的"一眼可查。

## 三、两套 RAG（检索容错要求不同，技术选型也不同）

**生成主链 · 术语注入 RAG**：检索对象是结构化术语库。**刻意不用向量**——术语注入要求零误伤，近似匹配在这里是负债；采用精确字符串匹配、长词优先防子串误命中、按批过滤只注入当批出现的词（token 成本可规模化）。向量在此仅用于提示近义词条。

**客服问答 · 经典向量 RAG**：知识库是随构建分发的产品手册（与程序同版本编译，文档永不漂移）。按 markdown 标题语义切块（600 字上限，超长按段落聚合），块内带标题路径一起嵌入；384 维多语向量、L2 归一化后点积即余弦，top-5 连同出处注入 system prompt。**每层都有降级**：向量服务不可用 → 关键词打分检索（CJK 双字组合、标题 3 倍权重）→ 模型未配置 → 引导语。

## 四、可靠性工程（生产环境实战）

| 问题 | 根因 | 修法 | 实测 |
|---|---|---|---|
| 视频块状漏翻 | 转写 VAD 门槛拦掉轻声段 | 阈值 0.5→0.3 + 缺口补翻（对账「有语音无字幕」剪出重转） | 101 → 109 条 |
| 译文整块未翻译 | 模型漏返回行，旧策略"部分成功即接受" | 按**缺行子集**补翻，最多三轮 | 治愈单批 17/40 行丢失 |
| 大面积台词消失 | 反幻觉过滤器误杀（耳语内容 VAD 失聪） | **熔断机制**：待删超 25% 判定 VAD 不可靠，整体放弃删除 | 挽回被误删的 190/326 条（58.7%） |

> 最后一条最值得一提：**防御机制本身成了攻击者**。同一个症状可以有多个独立根因，每修一层都要重新用数据定位下一层。

## 五、技术栈

| 层 | 技术 |
|---|---|
| 编排后端 | Java 21 · Spring Boot 3.5 · MyBatis-Plus · H2（单文件嵌入库） |
| AI 微服务 | Python FastAPI · faster-whisper（本地 ASR）· Silero VAD · fastembed（384 维多语向量）· edge-tts |
| 前端 | Vue 2.7 · Vite · Element UI |
| 外部集成 | 任意 OpenAI 兼容端点 · Groq Whisper · Gemini · Tavily/博查/Serper · **LangSmith** |
| 媒体 | FFmpeg（抽音频 / 切片 / 静音检测 / 字幕烧录） |
| 自研 | Agent 编排、预算约束、JSON 协议信封、向量检索、RAG、观测层 |

**为什么不用 LangChain / LangGraph**：① 编排必须住在 JVM（全部状态在 Java 侧），而 Python 边车在架构里被设计成"随时可死"的无状态进程，把大脑放进最允许不可靠的进程等于可靠性倒置；② 架构原则是**禁止动态控制流**，而循环与条件路由恰是框架的核心卖点，图接线部分我只写了约 200 行，真正难的（取消语义下的部分结果抢救、证据核验、逐层降级）框架不替你写；③ 用户自填杂牌端点意味着抽象层每周都在漏。**但观测接的就是 LangSmith**——原则是*在数据边界拥抱生态，在控制流上保持所有权*。

## 六、工程质量

- **184 项单元测试**，置信度算分、切块、仲裁、时间轴修正等核心算法**全部纯函数化**设计，可穷尽测试
- 逐环"清洗账单"日志：每道关口删了多少条一目了然，漏数据时不必翻日志猜
- 降级总则：除垃圾源拦截外，**任何单点故障都不终止任务**，每步必有降级产物且降级必打标

## 七、快速开始

```bash
# 后端（需 JDK 21+）
cd backend && ./mvnw.cmd spring-boot:run

# 前端
cd frontend && npm install && npm run dev

# AI 微服务（可选，提供本地 ASR / 向量 / 配音）
cd ai-service && python -m uvicorn app.main:app --port 8001
```

首次登录在「设置 → API 密钥」填入翻译模型配置（任何 OpenAI 兼容接口）即可使用。语音识别可选 Groq 云端或本地 Whisper。

> 便携分发版内置 JRE、Python 运行时与 Whisper 模型（约 8GB），解压双击 `start.bat` 即用、零依赖；这些二进制不纳入版本库。

```
backend/src/main/java/com/aifanyi/
├── agent/          多智能体系统
│   ├── node/       流水线节点（场景推测/扇出/仲裁/置信度/状态机/RAG翻译）
│   ├── llm/        JSON 协议信封、三级容错解析、提示词
│   ├── search/     搜索 provider + 权威域名核验
│   ├── vector/     嵌入客户端 + 内存向量索引
│   ├── trace/      trace 记录 + LangSmith 上报
│   └── profile/    领域专家档案（内置 5 个 + 用户自建）
├── support/        客服 RAG（切块 / 检索 / 问答接口）
├── llm/            翻译模型客户端（批次补翻、术语注入）
├── media/          时间轴修正、反幻觉、VAD 熔断
└── service/        任务编排、转写链、设置
ai-service/app/     FastAPI：ASR / VAD / 嵌入 / TTS
frontend/src/       Vue 页面（含运行现场面板、智能客服悬浮球）

```
